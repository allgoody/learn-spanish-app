# Project Rules: learn-spanish-app

## Tech Stack

- Astro 7.3.1 (latest) + Tailwind CSS 4.3 + React 19 (islands), mobile-first — INSTALLED in `astro/`
- TypeScript strict (Astro default), vitest 5 (dev) for `.mjs` script tests
- No backend, no runtime API keys; scripts are plain ESM `.mjs` (Node built-ins only, no tsx/axios/lodash)

## Architecture

- **Build-time gloss pipeline**: script downloads book → cleans → tokenizes → dedupes word forms → LLM batch-glosses with context sentences → commits `glosses.json` (word → {lemma, pos, ru, grammar, note})
- **Book fetch pipelines**: **Gutenberg via `scripts/fetch-book.mjs`** — config-driven (`scripts/data/gutenberg/{id}.json`), two modes: `indice` (numbered table of contents + PRÓLOGO; andanzas) and `roman` (preface + bare roman-numeral chapters up to a FIN colophon, dropping the publisher pages; barraca). Verify a parser refactor by regenerating an already-committed book and checking `git status` is clean — andanzas is the regression fixture. **Wikisource es via `scripts/fetch-wikisource.mjs`** — config-driven (`scripts/data/wikisource/{id}.json`); two extractors: `story` (`extractStoryText`, needs the `ws-h3-medio` heading, one page = one chapter; selva) and `article` (`extractArticleText`, every `<p>` on a single flat page, e.g. `San Manuel Bueno, mártir`), optionally split into chapters by paragraph markers via `splitSections` (`sections[]` with `marker` = the first line of the section's opening paragraph). A marker line that is just the heading is dropped, so a work title sitting on line 1 of the first body paragraph does not duplicate the page H1. MediaWiki `action=parse&prop=text`; 300ms polite delay between pages; 3-attempt/5s-backoff retries. New book = config + run + wire into `lib/books.ts`
- **Gloss pipeline resilience (plan v2)**: `glosses.json` is written incrementally after EVERY batch so an interrupted run resumes; up to 3 context sentences per key (first 3 distinct occurrences, located by case-insensitive `indexOf` — the tokenizer emits no positions); parse/merge logic lives in pure tested helpers (`scripts/lib/gloss-parse.mjs`: `parseBatchResponse`/`mergeGlosses`/`pendingKeys`). CLI knobs: `--think <low|medium|high>` (ollama thinking level; omitted = provider default), `--timeout <ms>` (per-request abort, default 120000 — too low for thinking runs on big batches), `--limit <n>` (gloss only the first N pending keys — for timing experiments). Measured on `deepseek-v4.1-flash:cloud --think high`: 50-key batch ≈ 70 s, 25-key ≈ 35–50 s, so batch 50 is the throughput default; 9,328 keys ran with 0 aborts
- **Tokenizer (`scripts/lib/tokenize.mjs`)**: `WORD`/`WORD_CHAR` must cover every letter that occurs in the content, not just Spanish — Catalan/Valencian `à è ì ò ù ç` are included (a missing letter splits a word into fragments: `Bòn` → `B`+`n`, `Ròcha` → `R`+`cha`, and the stray `b`/`n`/`r` fragments become gloss keys with popups mid-word). Changing the class means regenerating `tokens/` for every book that uses the new letters (andanzas had ç×16) — selva proved unaffected. Standalone `é`/`ó` are NOT artifacts: they are the 1898 spellings of `e`/`o` and get a `modern` gloss
- **Per-page precompiled gloss libraries** — each chapter page loads only its own words+phrases (inlined/small JSON); phrase recognition via longest-match ("a pesar de" = one unit). `import.meta.glob` eager in frontmatter is fine — it stays server-side; island props serialize per-page. **Size ≈ 300 bytes per key** and it ships inside the page: the 11,796-word San Manuel novella chapter (2,838 keys total, 1,591 in that chapter) is a 2.2 MB HTML page / 231 KB gz, vs 1.42 MB for andanzas' worst
- **Gloss schema (future-proof, all fields optional)**: lemma, pos, ipa, ru, grammar (STRING explaining THIS surface form, e.g. "pretérito imperfecto, 1ª/3ª pers. sing." — not an object), cefr, modern (archaic→modern), false_friend, note
- **Reader UI**: every word rendered as a span with `data-word`; ONE delegated event handler; desktop tooltip on click / bottom-sheet on tap (mobile). **Desktop tooltip is non-blocking** (2026-09-27): `pointer-events-none` so clicks pass through to words underneath (next word opens without dismissing), and it flips below the word when there is no room above; trade-off: tooltip text not selectable. Paragraphs preserved via `splitParagraphs` (2+ consecutive `\n` tokens = break) — never render a whole chapter in one `<p>`. Popup has `popupRef`; close-on-outside rules must exclude targets inside the popup (hovering the tooltip / tapping or scrolling inside the sheet must NOT close it). Glossable spans: `tabindex="0" role="button"`; Enter/Space opens
- **i18n**: `chapterCount(n, lang)` with `pluralRu(n, one, few, many)` — Russian plural rule: n%10==1 && n%100!=11 → one; n%10 in 2..4 && n%100 not in 12..14 → few; else many (41 → "41 глава", NOT "41 Главы")
- **Analytics & consent (2026-09-27)**: `CookieConsent.astro` (rendered from Layout) holds the banner + GA4 loader. GA id `G-RZLGCDEZSN`. **Consent-gated** — the gtag.js script is injected only after "Принять"; no pre-consent pings, no cookie before that. Uses the canonical `function gtag(){dataLayer.push(arguments)}` form (array-form commands are silently ignored). Choice in `localStorage["cookie-consent"]`; the privacy page has a reset button. Never load GA via Partytown
- **Structured data (JSON-LD, 2026-09-27)**: `lib/jsonld.ts` exports `breadcrumbs(crumbs, base)` (absolute URLs); every page emits JSON-LD via `components/JsonLd.astro` — home `WebSite`+`Organization`, book landing `Book`, reader `Chapter` (+`isPartOf` Book, `position`), words `LearningResource`, about `AboutPage`, privacy `WebPage`, all deeper pages `BreadcrumbList`. `PrivacyPolicy` is NOT a schema.org type
- **Agent discovery (ARD / ai-catalog, 2026-09-27)**: `astro/public/.well-known/ai-catalog.json` is the spec's well-known URI manifest (`specVersion: "1.0"`, `host`, one entry → `llms.txt`); `astro/public/_headers` serves it as `Content-Type: application/ai-catalog+json` (the media type is what identifies the document); `Layout.astro` adds `<link rel="ai-catalog" type="application/ai-catalog+json">`. Cloudflare's "agent discoverability" check fetches that path and reports the 404 HTML page as malformed JSON when it is missing. Conformance is deliberately Minimal/Discoverable: NO Trust Manifest (the spec forbids an empty one — `identity` plus a signature/attestations is required), and `host.identifier` is the bare domain, not `did:web:niceio.com`, because no DID document is hosted
- **Routing model (decision record `idea/routing.md` — read before touching URL structure)**: flat URLs — content language is DATA (`lang` field on BookMeta/WordCategory), never in URLs. Translation language = app setting (UI lang). Word lesson ids are per-language slugs (`/words/pronouns/` es, `/words/pronoms/` fr later). Chapter URLs `/books/andanzas/{slug}` are permanent — no `_redirects`. Source language is NOT a persistent setting (chooser sections only). `<html lang>` = content language on content pages (Layout `contentLang` prop + `data-content-lang` marker; `setLang` skips the lang override when the marker is present, so a UI switch can't clobber content lang). Glosses stay RU-only until the per-language gloss data task (routing.md §7). **SEO titles/descriptions are per-locale data** (`lib/seo.ts`, `seoLang = "ru"`) — pages call `seo[seoLang]`, adding a language = map entries + URL routing, no template changes. Future UI-language-in-URL model: routing.md §8
- **URL restructure EXECUTED 2026-09-05** (plan `.pi/plans/restructure-routing/`, 11 WPs / 3 phases): chooser at `/` (per-language sections from `languages` registry), generic `/books/[book]/` landing, generic reader `/books/[book]/[slug]` (chapter URLs unchanged), `/words/[category]/` + pronouns lesson (69 entries, 9 groups, RU content). `lang` field on BookMeta/WordCategory; Layout `contentLang`/`description` props; `setLang` guard. Verified: astro check 0 errors, build 44 pages, 51 tests, 5 routes probe 200. Deployment pending user go-ahead
- **Words lesson schema** (`src/data/words/*.json`, `WordEntry` in `lib/types.ts`): `{ es, ipa?, pos, ru, example?: {es, ru}, grammar?, note? }`. **IPA convention**: broad, seseo/neutral (matches LatAm coverage — voseo, ustedes), slashes stored IN the data, rendered as-is (reader glosses use the same convention). Castilian `/θ/` swap = data-only change. **Example convention**: one short learner-level sentence per entry, most common form for multi-form entries (mi/mis → "Mis amigos…"), RU translation always included; rendered italic es — ru under the translation
- **Words categories (2026-09-27, plan `add-word-categories`)**: `src/lib/words.ts` is the ONLY shared file — 8 categories in the contracted display order: pronouns, core-verbs, prepositions, conjunctions, adverbs, numbers, interjections, frequency; **`pronouns` MUST stay `[0]`** (WordLesson/Chooser tests). Adding a category = data JSON + a `test/data/words/{id}.test.ts` that imports the JSON DIRECTLY + one import/array entry; the chooser, `/words/[category]/`, sitemap and JSON-LD are all generic. 775 entries total. **`frequency.json` is GENERATED, not authored** — `scripts/build-frequency-words.mjs` + `scripts/lib/frequency.mjs` merge the 4 books' glossaries by (lemma,pos) majority vote ignoring noisy labels (`name`/`other`/empty `ru`), count lemmas over every token, keep the top 200, group by RU POS label; output must be byte-identical across runs. Run from `astro/`: `node scripts/build-frequency-words.mjs`. Per-category curated files use exactly the `pronouns.json` compact style (2-space indent, one entry per line, slashes in `ipa`, `es` unique within a group)
- Book data as plain JSON under `src/data/books/{id}/` (meta.json, chapters/, tokens/, glosses/) loaded via `import.meta.glob` — NOT content collections

## Design System

- Footer must include subtle 'Made by CTDev' credit linking to <https://ctdev.dev/ru/> (target=_blank, rel=noopener noreferrer, ~0.65rem, muted, underline on hover). **RESTYLED 2026-09-05**: the old ~0.6 opacity failed contrast (2.26:1); user approved removing the opacity — the muted token alone passes 4.5:1 in both themes (stone-500 on white 4.72:1, stone-400 on stone-950 7.88:1). No opacity reduction on the credit anymore. **Href changed to /ru/ 2026-09-05**
- **Footer nav (2026-09-27)**: About (`/about/`) + Privacy (`/privacy/`) links sit above the CTDev credit (i18n `about`/`privacy`, aria-label `footerNav`)
- **Sticky footer layout** (2026-09-05): body is `min-h-dvh flex flex-col`; page content wrapped in `<div class="flex-1">` so the footer anchors to the viewport bottom on short pages. Use `min-h-dvh`, NOT `min-h-screen` — 100vh cuts the footer on mobile when the address bar collapses
- **Standalone template lives in `template/`** (repo root, not astro/): `style.css` + `kitchen-sink.html` + `STYLE-GUIDE.md`. Design language = astro site's: stone neutrals + amber accent (amber-700 #b45309, stone-200 borders, white bg, system-ui, radius 4px)
- **Dark theme mechanism** (template): all colors are CSS custom properties; `[data-theme="dark"]` forces dark, `[data-theme="light"]` forces light, otherwise `@media (prefers-color-scheme: dark) :root:not([data-theme="light"])` follows the system
- **Contrast strategy** (template): light mode = 700-level semantic colors (emerald-700/amber-700/red-700/sky-700) so white button text passes 4.5:1; dark mode = 400-level colors with dark text via `--color-on-accent` (#ffffff light / #0c0a09 dark). Badges/alerts reuse the same tokens
- **Link affordance (a11y, 2026-09-27)**: an inline link inside a block of text MUST NOT be distinguishable by colour alone (WCAG 1.4.1). Give it a persistent underline — `class="text-accent underline underline-offset-2"` — not `hover:underline`: accent amber-700 vs muted stone-500 is a 1.04:1 luminance ratio, so hue is the only cue and Lighthouse's `link-in-text-block` audit fails. Standalone links (footer nav, the CTDev credit) are exempt — the audit only covers links within text blocks, and the credit's hover-underline style is user-approved
- **Modal component**: closed by default (`display:none`), `.modal.open` shows it; kitchen-sink wires open/close/overlay/Esc + focus management (focus in on open, return to trigger on close)

## Lessons

- **schema.org type check (2026-09-27)**: `Chapter` EXISTS (subtype of CreativeWork); `PrivacyPolicy` does NOT — use `WebPage`. Verify a type at `https://schema.org/<Type>` before emitting it (unknown types return no content)
- **Corpus gloss IPA is Castilian (2026-09-27)**: committed `glosses.json` `ipa` values use `/θ/` (`decir /deˈθiɾ/`, `vez /beθ/`). Any GENERATED category that copies `ref.ipa` (the frequency pipeline) inherits it and breaks the project's locked seseo convention — authored content must stay seseo, and generated output should map `/θ/`→`/s/`. 11 frequency entries carried it; flagged rather than silently fixed because the plan's IPA-normalisation spec was exhaustive
- **Consent-gated GA4 (2026-09-27)**: Partytown loses the landing pageview and array-form `dataLayer.push([...])` is silently ignored — use the canonical `gtag()` arguments form on the main thread. Loading only after explicit consent avoids both and keeps Lighthouse clean
- **jsdom placement test (2026-09-27)**: to drive an above/below branch, `Object.defineProperty(HTMLElement.prototype, "offsetHeight", { get: () => N })` and override the target element's `getBoundingClientRect` before the click

- **Output verbosity (user rule)**: keep the normal verbose style — detailed progress updates, explanations, status reports in chat. Not more, not less. **Long-running jobs (e.g. the gloss pipeline): the user wants LIVE progress updates — report batch progress as it happens, don't wait silently for completion.**
- **Latest Astro is 7.3.1 (not 5.x)** — all APIs the plan uses (create-astro flags, `astro add tailwind`, `import.meta.glob`, `getStaticPaths`, `astro check`, JSON imports, `client:*`) are unchanged in v6/v7; Node 22+ required; `@latest` everywhere
- **The Astro minimal template ships NO `src/layouts/Layout.astro`** — only `src/pages/index.astro` + `src/styles/global.css`; a plan saying MODIFY a scaffolded Layout.astro is wrong, it must be CREATE
- **Body-only distinct word forms ≈ 11,761 → 236 batches of 50** — counting front matter inflates to ~12,270; measure body only (from PRÓLOGO to END marker)
- **The book has 41 essays, not 37** — verified against the actual Gutenberg text; the ÍNDICE has 41 entries
- One essay title spans two all-caps lines (`EL CRISTO YACENTE DE SANTA CLARA` + `(IGLESIA DE LA CRUZ) DE PALENCIA`) — title matching needs a two-line join fallback
- Index continuation logic: a line WITHOUT a trailing page number STARTS a wrapped entry (does not continue the previous one)
- Body has 48 all-caps lines but only 41 are titles (7 versalitas false positives: RECUERDO DE MALLORCA, EL CAMPO ES UNA METÁFORA, JUNTO A LA VIEJA COLEGIATA, Roman numerals I–IV) — always match against index titles, never split on all-caps lines alone
- **Plan review lesson: a "resumable" script that only writes its state at the end is not resumable** — persist incrementally (glosses.json after each batch)
- **Plan review lesson: WP ordering applies to EVERY new prop, not just the obvious ones** — a page passed `description` to Layout before the WP that added the prop → `astro check` ts(2322) (verified empirically with a probe page). When reordering WPs, update all cross-refs (contexts, Shared Context, CONTEXT.md gotchas). And: a static no-FOUC guard is bypassed by the runtime setter — guard `setLang` too (data-content-lang check)
- **Plan review lesson: hover/tap popups must exclude the popup element from close-on-outside logic** — capture-phase scroll listeners fire for scrolls inside the popup; mouseover fires when entering the popup
- **Plan review lesson: Russian pluralization needs a real rule** — "41 Главы" is wrong; use pluralRu (41 → "41 глава")
- **`runs.all()` takes plain objects `{ key, ...params }`, NOT `runs.run()` promises** — passing run promises throws "runs.all item N has an invalid key" (the destructure reads `key` off the promise = undefined). Pattern: `const [a, b] = await runs.all([{ key: 'a', agent, task }, { key: 'b', agent, task }])`; use `runs.run('k', {...})` only for single sequential children. Validation throws before any child launches, so a failed workflow leaves no orphans
- **`api/tags` does NOT list `deepseek-v4-flash:0731-cloud`** (only gemini-3-flash-preview:latest, qwq:32b) but the chat endpoint ACCEPTS it — the local ollama proxies cloud models (response model name: `deepseek-v4-flash:0731`). `api/ps` shows nothing loaded for proxied models — NOT a sign of a dead pipeline. Verify a model works with a tiny `curl -m 30 http://localhost:11434/api/chat -d '{"model":"<name>","messages":[{"role":"user","content":"hi"}],"stream":false}'`
- **Subagent status display is misleading**: turns/ctx don't grow while a subagent is blocked in a long bash call — the child process does the work. Don't kill a subagent just because it looks idle; check the actual child process / output files first
- **Guardrail gotchas**: `taskkill //PID` gets mangled → use `powershell -Command "Stop-Process -Id N -Force"`. `cd astro && nohup ... > ../.tmp/...` trips the path guardrail → run from repo root: `node astro/scripts/...` + `.tmp/gloss.log` (scripts resolve their own paths via `__dirname`)
- **WP-3 fetch script**: the PRÓLOGO special case must advance `nextTitleIdx` past the index's first entry, else every section after the prólogo is missed
- **Tokenizer**: word regex must include digits (`[A-Za-zÁÉÍÓÚÜÑáéíóúüñ0-9]+`) — a letter-only regex makes "all digits → null" dead code
- **`import.meta.glob` in Astro pages must live INSIDE `getStaticPaths()`** — the docs' Caution: getStaticPaths runs in its own isolated scope and can only reference file imports, not frontmatter variables. A frontmatter `const tokenFiles = import.meta.glob(...)` used only in getStaticPaths gets DROPPED by the compiler (no warning) → build fails with "tokenFiles is not defined". Move the glob calls into getStaticPaths (Vite still transforms them there).
- **Biome autofix** rewrites quotes; plan success checks may grep for exact quote style (e.g. `format: "json"`) — restore if biome flips it
- **LSP JSON false positive after edit**: a valid JSON file can briefly report "End of file expected" from a stale LSP buffer right after an edit — verify with `node -e "JSON.parse(...)"` and `touch` the file to refresh the server before trusting the diagnostic
- **Plan grep checks can match i18n string dicts**: WP-8's `grep "← Home"` check matched the `backHome` string WP-4 itself mandates — check intent (no hardcoded links in templates) over literal grep when the plan's own WPs conflict
